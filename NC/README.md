# NC

**NC** — демонстрационный проект CAD-аддона для nanoCAD в составе решения CommonLib. Он показывает, как собрать приложение на основе общих библиотек решения, подключить инфраструктуру хоста и организовать точку входа аддона.

Проект служит примером интеграции компонентов CommonLib. Его код не является самостоятельной универсальной библиотекой: при создании рабочего аддона его обычно используют как ориентир для настройки зависимостей, регистрации сервисов и взаимодействия с API nanoCAD.

## Назначение и состав

В проекте находятся:

- **EntryPoint** — точка входа аддона. Реализует контракт `IExtensionApplication` CAD-хоста и управляет инициализацией и завершением работы.
- **Commands/Test** — демонстрационные команды для проверки и изучения взаимодействия с nanoCAD и сервисами CommonLib. Они компилируются только в конфигурации `DEBUG`.

Основная логика общих команд и CAD-сервисов вынесена из демонстрационного проекта в библиотеку `Common.NC`. Реализации инфраструктурных адаптеров nanoCAD находятся в `Infrastructure.NC`.

## Архитектура и зависимости

Проект `NC` использует следующие проекты решения:

| Проект | Назначение |
| --- | --- |
| `Abstractions` | Контракты сервисов, настроек, сообщений и логирования |
| `AddOnRuntime` | Создание и настройка контейнера сервисов аддона |
| `MulticadInterop` | Совместимость и взаимодействие с API MultiCAD |
| `Common.NC` | Общие команды, CAD-вспомогательные классы и контекст аддона |

В ходе инициализации `AddOnRuntime` создаёт корень композиции и регистрирует реализации сервисов. `EntryPoint` получает сервисы через `AddOnContext`, после чего запускает фоновую проверку обновлений и выводит сведения об аддоне, CAD-хосте и системе.

Реализации сервисов, специфичные для nanoCAD, собраны в `Infrastructure.NC`. Демонстрационный проект не должен дублировать эти реализации или переносить к себе общую функциональность из `Common.NC`.

Упрощённая схема зависимостей:

```text
NC
├── Abstractions
├── MulticadInterop
├── AddOnRuntime
│   ├── Settings
│   ├── LogBootstrap
│   ├── Infrastructure
│   └── Infrastructure.NC
└── Common.NC
    ├── Abstractions
    └── Updater
```

## Жизненный цикл аддона

Класс `EntryPoint` реализует стандартный для CAD-расширения жизненный цикл:

1. **Initialize()** — создаёт корень композиции при первом запуске, инициализирует `AddOnContext` и получает необходимые сервисы.
2. Проверяет расположение аддона и предупреждает пользователя, если пакет загружен не из ожидаемого каталога.
3. Запускает автоматическую проверку обновлений в фоновом режиме, не блокируя инициализацию CAD-хоста.
4. Записывает в журнал сведения об аддоне, CAD-хосте и системе; при включённой настройке выводит информацию о зарегистрированных командах.
5. **Terminate()** — выполняет завершающие действия при выгрузке аддона.

Ошибки инициализации обрабатываются в точке входа. Ошибки фонового обновления и вспомогательного вывода не должны прерывать загрузку аддона.

## Демонстрационные команды

Команды из каталога `Commands/Test` предназначены для отладки и изучения API. Они доступны только при сборке с символом `DEBUG` и не входят в состав Release-сборки.

Примеры проверяемых сценариев:

- ручной вызов инициализации через `EntryPoint`;
- вывод информационных, предупреждающих и ошибочных сообщений в командную строку;
- вывод сообщений через GUI-уведомления;
- запрос ответа пользователя через диалоговые сервисы;
- получение и вывод сведений об аддоне, CAD-хосте и системе.

Имена команд формируются с использованием `CommandPrefix.Value`. Префикс генерируется перед компиляцией из имени решения: для большинства решений используется формат `drz_<SolutionName>`, а для решения `drzTools` — само имя решения. Поэтому фактические имена команд зависят от имени решения, в котором выполняется сборка.

Общие команды (информация о командах, настройки, уровни логирования и управление обновлениями) находятся в `Common.NC`, а не в демонстрационном каталоге `NC/Commands/Test`.

## Сборка

Параметры проекта:

- целевая платформа: `.NET 6`, `net6.0-windows`;
- архитектура: `x64`;
- семейство CAD-хоста: `NC`;
- API хоста: пакеты `MultiCAD.NET` и `nanoCAD.Platform.NET`, версии которых задаются в файлах проекта и общих настройках сборки.

Проект явно импортирует при наличии файлы `$(SolutionName).Build.props` и `$(SolutionName).Build.targets`. Путь импорта задан относительно каталога проекта и в текущей структуре указывает на корень репозитория CommonLib. При сборке самого CommonLib значение `SolutionName=CommonLib`, поэтому подключаются `CommonLib.Build.props` и `CommonLib.Build.targets`. При использовании проекта в другом решении значение `SolutionName` задаётся потребителем; в этом случае настройки CommonLib не импортируются. Потребитель должен задать `SolutionName` на раннем этапе, например в своём `Directory.Build.props`. Подробности приведены в разделе [Общие параметры MSBuild](../README.md#общие-параметры-msbuild).

Проект также импортирует `Shared.NC.props`. Этот файл задаёт общие параметры nanoCAD-проектов и генерирует префикс команд.

Для сборки требуется Windows-среда с установленным .NET 6 SDK и доступом к используемым NuGet-пакетам. Для запуска и проверки команд требуется совместимый nanoCAD с поддерживаемой платформой API.

Сборка проекта сама по себе не заменяет установку аддона в nanoCAD: для проверки загрузки необходимо разместить собранные файлы в структуре, ожидаемой CAD-хостом и механизмом загрузки аддонов.
